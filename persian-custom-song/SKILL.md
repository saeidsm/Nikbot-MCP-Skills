# Persian custom song

This project-neutral workflow includes no provider credentials, production integration paths, model entitlement or music-generation runtime. Configure a permitted provider separately; never assume a brand-like filename proves a working connection.

## Brief
Extract exact names and intended pronunciations, context, audience, occasion and requested mood/groove/genre. Respect the latest typed spelling over uncertain transcription. Support multiple people without merging them. If essential information is missing, ask one grouped question; do not repeat answered questions. A deliberately non-personal song needs no invented person.
Distinguish emotion, use, tradition, meter and tempo. A solemn song should not inherit cheerful defaults. Propose reversible musical details when unspecified, not permanent presets. Keep personalized facts in the task, not in the reusable skill.

## Lyrics and pronunciation
Use the user's selected lyric-generation route when authorized; do not claim a named model wrote locally drafted lyrics. Prepare title, plain Persian lyrics, pronunciation glossary, singing/diacritized text, section plan and separate musical direction. These are planning fields, not necessarily API fields.
Keep verse lengths singable, breath points practical, rhyme natural and meaning accurate. For full diacritization, preserve the canonical base text exactly while annotating permitted marks. Verify base-letter equality separately from correct lexical pronunciation; a high mark count proves neither. Preserve unmarked names alongside singing forms. Apply owner-confirmed readings consistently and clarify genuine pronunciation conflicts.
Match the intended audience; do not impose childlike phrasing on adult music. Avoid invented achievements or hurtful jokes. Keep respectful material respectful.

## Verify provider and budget
Inspect permitted code/docs and redacted runtime metadata for the actual endpoint, model, schema, lyric limits, supported styles and status route. Never dump credentials or environment variables. Confirm current price/balance and a concrete authorized spending cap before paid calls under the applicable rules. Approval of lyrics is not automatically spending approval.
Read-only-looking preflight wrappers may write admission records: distinguish these effects. Do not spend merely to test connectivity. When execution is unavailable, deliver the reviewable brief and state the missing prerequisite.

## Submit and recover
Map only verified fields; do not invent API parameters from planning labels. Keep sung text separate from genre/instrumentation instructions. Check lengths without silently truncating names, marks or sections. Preserve existing rate limits, budget gates and durable job identity.
Submit once within authorization, record sanitized request identity and provider task ID, then poll with bounded backoff. Reconcile a timeout or unknown delivery before any retry. If idempotency is unsupported, say so; do not claim an application ID guarantees provider deduplication. A failed track does not itself authorize another charge.

## Deliver
Retrieve actual audio before temporary links expire. Verify content type, nonempty bytes and available playback/duration evidence. Listen or use permitted audio inspection for critical names and intelligibility. Report an unverified pronunciation rather than claiming it is correct. Attach downloadable audio where supported, with concise style/status/cost and remaining limitations. Never publish private lyrics, identifiers or signed media links into a public skill or permanent public log.
