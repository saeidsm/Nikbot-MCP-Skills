# Shahrzad gift account

Deliver a usable gift, not only a draft or generation receipt. Follow the existing Shahrzad product workflow; do not build a new onboarding system or change production code just to complete a gift.

## 1. Establish the brief once

Extract parent contact, exact character names and pronunciations, age, personality, relationships, source photos, story seed, learning goals, language pair, story mode, visual style, narrator and optional song direction. Keep all values request-scoped. Do not bake family details or provider identifiers into this skill.

Use the supplied brief without repeated questions. Ask only for missing details that block the next action. If bilingual languages are unspecified, propose Persian/English as an assumption, not a verified account preference. Resolve labels such as “home style” against the actual application's options rather than inventing an enum.

Distinguish **saved characters** from supporting characters mentioned only in a story. Create only the profiles requested. Do not infer appearance from a name or fabricate a photo-based likeness while images are missing. Continue independent preparation while awaiting photos.

## 2. Check authority and access

- Verify the connected account and intended service before mutation. Use an existing supported app integration or the user's authorized browser session; discover actual operations and schemas.
- Treat child names, ages, photos and private family details as sensitive. Use only explicitly authorized destinations and purposes. A request to set up Shahrzad is not blanket permission to upload photos to another vendor or publish the package publicly. Check the real provider path and disclose/obtain any missing destination approval before transmitting sensitive details.
- Keep source photos and personal identifiers out of public repositories, diagnostic transcripts and reusable examples. Use private artifact storage. Never print secrets or send password/reset tokens in ordinary messages.
- Use supported onboarding/verification and account access controls. Do not forge phone verification, reuse an admin password, bypass OTP, or give an account access to another family's records. Account preparation does not authorize sending an unsolicited invitation/SMS; report any mandatory notification before triggering it unless already approved.
- Separate account setup from subscription purchase or credits. Honor explicit task-scoped spending permission and applicable confirmation rules. Verify the actual cost basis and request count, avoid unlimited retries, and ask only for genuinely missing approval. No paid connectivity probes.

## 3. Inspect before create

Read current parent-account match, character list and existing story/song jobs through authorized routes. Normalize phone numbers only for matching; retain the canonical number privately. Never merge or overwrite an existing family's data. If a match is uncertain, stop that mutation and resolve ownership.

Record one private progress checklist using [the handoff template](references/delivery-checklist.md). Retain only safe internal object/job IDs and evidence necessary for recovery. If another worker owns this gift, resume its handoff rather than starting a parallel duplicate.

## 4. Prepare and save the package

1. Create or reuse the correct parent account using the supported flow. Identify how the parent will sign in and what verification remains; never claim login was tested when only an account row exists.
2. Create the requested character profiles, using provided photos only with authorized upload scope. Verify each profile is persisted under the correct family and its preview loads.
3. Draft an age-appropriate story with the requested goals conveyed through choices and consequences, not lectures. Keep adult responsibility realistic: a child's leadership should not imply sole responsibility for young children's safety. Preserve the user's plot while making supervision and a clear adult contact plan explicit.
4. Select the actual requested story mode, illustration style, language pair and default narration. Save story content through supported routes; verify names, relationships, bilingual consistency and selected settings.
5. Submit authorized illustration/narration jobs once. Retain job IDs and reconcile before retrying a timeout. Verify actual images and audio, not only success flags.
6. If requested, use the installed `persian-custom-song` skill for fully diacritized Persian lyrics and the verified music integration. Keep canonical names separate from singing pronunciations. A requested existing voice profile must be mapped to a supported request field and read back; mentioning a singer in a style prompt is not evidence of voice selection. Respect applicable voice-use restrictions. Verify the produced audio and disclose any unsupported voice control rather than substituting silently.

## 5. Reconcile, verify and hand over

On ambiguous submission, inspect persisted jobs and provider status before any retry. Do not release locks, delete admission records, or submit elsewhere to evade a duplicate guard. Report pending separately from failed. Resume from the last verified stage.

Check only relevant acceptance cases: correct account ownership; requested characters; accessible story; requested languages and art; narration/song playback; working parent entry route. Verify the intended account view, not only an admin preview. Do not manufacture a successful login or bypass verification to test it.

Give the owner a short readiness report with a private product link, sign-in method, completed items and any remaining parent action. Do not send passwords, internal admin routes or raw provider URLs. Distinguish **created**, **generated**, **saved to account**, **playback checked**, and **ready to deliver**. Deliver to the owner unless direct recipient outreach was expressly authorized.

Keep this skill generic. Save any operational lessons as redacted workflow guidance, never a family's personal record.
